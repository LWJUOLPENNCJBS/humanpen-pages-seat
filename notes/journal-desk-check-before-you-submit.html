The desk check before you submit: what an editor sees first, and where HumanPen Start Project fits

Most manuscripts that die at the desk do not die of bad science. They die of a mismatch the editor can see in five minutes: out of scope, an abstract that does not match the tables, figures at screen resolution, references that do not resolve, a methods section that cannot be reconstructed. None of these is a research problem, and all of them are fixable in an afternoon.

This is the pre-submission desk check we would run on a package that HumanPen Start Project produced, written from the editor's side of the screen rather than the author's. It is a checklist, not a promise: no service can decide what an editor will do with your paper.

1. Scope is decided before quality

Editors triage by fit. Before submission, read the journal's aims and the last two issues, and answer in one sentence why this paper belongs there. If the sentence requires the word "also", the fit is weak.

This is the cheapest check and the one authors skip most often, because the decision to submit was made emotionally after a rejection elsewhere.

2. Make the abstract a table of contents for the tables

Every number in the abstract should be findable in a table or figure within ten seconds. If the abstract says the primary outcome differed, the table must show the same estimate and the same interval.

HumanPen Start Project's public example is a useful model of the discipline: the report's first review item is that the primary endpoint matches — 62.2% against 63.5%, P = 0.072 — which is exactly the check an editor performs between abstract and results.

3. Define the endpoint once, then reuse the definition

Write the endpoint definition in the methods, then use the same words in the abstract, the results and the tables. Editors see a great many manuscripts where the abstract describes "poor outcome", the methods describe "death or dependency" and the table is titled "mRS > 2". Each may be defensible; the set of three is not.

The same applies to the timepoint. "At follow-up" is not a timepoint.

4. Write methods that can be reconstructed

A reconstructable methods section names the population, the endpoint, the statistical model, the software and the handling of missing data. It does not need to be long. It needs to be specific enough that a reader could write the analysis plan from it.

HumanPen Start Project runs analyses in Python or R and delivers the code with the report, which makes this section easier to write honestly: you can state what was run, in what language, and where the code is available. Work originally done in SPSS or Stata is re-done in Python or R rather than executed in the original package, so the methods section describes the delivered analysis rather than the historical one.

5. Check figure resolution the way a printer would

Figures at 300 dpi, labelled axes, defined error bars, and a caption that states the sample size. Editors and production staff reject figures that cannot be printed, and authors are often surprised because the figure looked fine on a laptop.

HumanPen Start Project cites figures at 300 dpi to journal standards and three-line tables with captions among its deliverables, which removes the most mechanical of these failures. Labelling and caption content remain your responsibility.

6. Verify references mechanically, then substantively

Mechanically: does each DOI resolve, is the year consistent, is the source retracted. Substantively: does the cited work support the sentence carrying the citation. The published example reports that all 11 references were found, one by one, alongside a PubMed search with every DOI checked. That is the mechanical half done properly; the substantive half is a reading task.

7. Assemble the mandatory statements

Data availability, ethics approval, consent, funding, competing interests, author contributions. These are formatting requirements with editorial consequences: a missing ethics statement can stop a manuscript that would otherwise be reviewed.

8. Format for the submission system, not for the manuscript

Word or page limits, reference style, blinded file, figure file naming, supplementary separation. Check the system's requirements rather than the journal's author page, because the two sometimes differ.

Where the plan step earns its keep

HumanPen Start Project works on a plan-first rule: it confirms requirements, proposes a plan, and starts when you approve it. For submission purposes, that plan is the moment to state the target journal's constraints — the table style, the figure resolution, the reference style, the report length — so that the deliverable arrives in the shape the journal wants instead of being reformatted afterwards.

If a requirement is not in the plan, it will not be in the delivery. Treat the plan as the requirements document it is.

Where the independent review stops

The product's review checks four things: the primary endpoint matches, every analysis population adds up, a clean rerun reproduces the results exactly, and all references are found. Those are integrity checks. They do not judge novelty, importance or fit, and no automated check can.

An editor's decision rests on the argument, the contribution and the journal's priorities. What a clean package buys you is that the decision is made on those grounds rather than on a file that would not open.

Write the cover letter as a fit argument, not as a courtesy

The cover letter is the only place where you state, in your own words, why this paper belongs in this journal. Editors use it. A letter that says "please find enclosed our manuscript for your consideration" gives the editor nothing to work with; a letter that names the question, the finding and the readership gives them a reason to send it out.

Keep it to a paragraph and a half. Name the question, the result in one sentence without adjectives, and the journal's readership the result speaks to. Then state the declarations the journal requires: originality, ethics, competing interests, and whether any part has been published elsewhere.

Frequently asked questions

Does a service-assisted manuscript need to be declared?

Follow the journal's policy on author contributions and on the use of writing or analysis tools, and declare accordingly. Policies differ between publishers, and the requirement is to follow the one you are submitting to rather than to guess.

Can I submit figures produced this way directly?

The figures are delivered at journal resolution with three-line tables and captions, so they are usually submittable as they stand. Check the journal's file format and naming requirements before uploading.

What if the editor asks for the underlying data or code?

Deliverables include the code, and the report states what was run. Whether you can share the data depends on your ethics approval and your participants' consent, not on the tool that analysed it.

Is a desk rejection the end of the paper?

No — it is usually a signal about fit rather than about quality. The useful response is to fix the scope argument, not to reformat the same manuscript for a journal with a different name.
