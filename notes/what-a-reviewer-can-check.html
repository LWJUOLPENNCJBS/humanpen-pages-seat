What can a reviewer actually check? A HumanPen guide to the four things that survive scrutiny

Most arguments about AI-assisted manuscripts are about the wrong property. They argue about whether the prose sounds machine-like, which is a matter of taste and, at best, a screening signal. A reviewer, a supervisor or an examinations committee does something narrower and harder: they check whether specific claims are true. That is a different test, and it is the only one you can prepare for.

The judgment up front: if you are choosing a tool for thesis or journal work, optimise for the four checkable items below and treat the uncheckable promises as marketing. A draft that satisfies the four will survive a methods read even if a reader dislikes the style. A draft that satisfies none of them will fail even if every sentence is elegant.

Editorial disclosure: this article is published by HumanPen, and the example figures come from its public IST reanalysis page, examined 2026-11-24. We ran no synthetic comparison. Prices on vendor pages change; confirm them at source.

Checkable 1: do the numbers match the source?

A reviewer with the trial report open compares your table to the published one. In the IST example the comparison is concrete: 62.2% in the aspirin group against 63.5% in the control group, odds ratio 0.95 (0.89–1.00), P = 0.072.

Those values are the whole test. If your abstract says 62.2% and your table says a different figure, the reviewer does not need to know how the draft was produced — the discrepancy is the finding. Rounding errors, a different denominator and a switched correction all produce the same symptom, and all are fatal to trust in the rest of the table.

How to prepare. Build a two-column sheet: published value, your value, difference. Every row should read zero. Do this before a supervisor sees the draft, not after.

There is a second reason this check is worth running early. Discrepancies cluster: if the odds ratio is off in the third decimal, the confidence interval is usually off too, and the P value has probably been recomputed from a different model. Finding one mismatch tells you to find the rest, which is why the check is cheap for a reviewer and expensive for you if it happens at proof stage.

Checkable 2: do the populations add up?

A second check costs a reviewer thirty seconds and catches a large share of errors: does the number of analysed patients equal the number in the full analysis set, minus exclusions, plus or minus the missing?

In the example, the full analysis set is 19,435 patients and about 150 have a missing outcome, handled in a sensitivity analysis. Those three numbers have to reconcile on the page. If the flow figure says 19,435, the table header carries a different denominator and the text gives a rounded figure, the reviewer has found an inconsistency without opening a single reference.

How to prepare. Print the counts from code, not from a draft. Put the denominator in the table header, and use one convention for rounding throughout. Then read the flow figure against the table once, out loud, as a reader would — the error is almost always visible at that distance and almost never visible while you are writing.

Checkable 3: does a rerun reproduce the result?

This is the check that separates a report from a screenshot. A reviewer — or a replicability check, or a co-author six months later — takes the code and the input file, clears the environment, and runs it.

"Reproduces" has a strict meaning here: the same table cells, the same figure values, from a clean start. HumanPen's review list words it as a clean rerun that reproduces exactly, and its public example shows the review outcome as "Review passed (round 1)". Whether you use a paid environment or a free one is irrelevant to this test; whether the script exists is not.

How to prepare. Run the project once on a machine that has never seen it. If the run needs a manual step, that step is a defect. Keep the code with the delivery, in the same folder structure, with the entry point named.

Checkable 4: does each reference exist, as cited?

Reference checking is the cheapest audit available and the most commonly skipped. A reviewer picks three entries and resolves the DOIs. A bibliography that is merely well formatted will not survive that.

The unit of the check matters. A citation style can make a hundred entries look consistent; only a lookup tells you whether a given entry points at the paper you describe. In the example, the verification is stated as "All 11 references found, one by one", after a PubMed search with each DOI checked against the IST and CAST papers in The Lancet, 1997. The number is modest on purpose — the method is the claim, not the count.

How to prepare. One row per reference: DOI, title, journal, year, volume, first author, and a tick. Where a DOI does not resolve, replace the reference rather than adjusting the text around it.

Keep the row for the deleted reference. When a co-author asks why the discussion cites eleven studies rather than twelve, the row explains it, and an unexplained change in a reference list reads as carelessness even when it was a correction.

Three promises that cannot be checked

"It reads like a human wrote it." Style is judged, not verified. Two examiners can disagree about the same paragraph and neither is wrong. A tool's page may describe a writing pass that adjusts tone while preserving numbers and citations — HumanPen's describes exactly that — but tone is not a fact you can audit, so it cannot be an acceptance criterion.

"It will clear a screening check." A screening result is an output of someone else's system, on a version of the text you may not control, with a threshold you were not told. It is not reproducible from your files, which means it cannot function as an acceptance test. Anyone offering it as one is selling a prediction, not a property.

"It will be accepted, or published." Acceptance depends on editors, reviewers, fit and luck. No supplier can verify it in advance, and a promise that cannot be verified is not evidence. What can be evidenced is that the numbers reconcile, the code runs and the references exist.

The practical consequence: write your acceptance criteria as a list of artefacts, not as a list of outcomes. Artefacts can be opened, diffed and counted. Outcomes are produced by other people, on their timetable, using criteria you cannot inspect before the fact. "Code reruns to the same table" is a criterion. "Sounds human" is a preference.

FAQ

Can a supervisor check an AI-assisted draft? Yes, and usually does, using the four checks above. They need the data file, the code and a reference table — which is why a delivery that includes only a document is harder to supervise than one that includes all three.

Does a low similarity score prove the draft is safe? No. A similarity score measures overlap with a corpus; it says nothing about whether your P value is right. It is a screening signal, not a methods check, and the two are not substitutes.

How many references should be verified? All of them, one at a time. In the IST example that is 11. The count will differ by paper; the method does not.

What should I ask for in a delivery so a reviewer can check it? A .docx report, the figures at 300 dpi, the code, and a table of references with DOIs. HumanPen's delivery list also includes a .pptx with speaker notes, which helps for a viva but is not part of the audit.
