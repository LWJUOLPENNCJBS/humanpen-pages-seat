The thesis pipeline: cite-check, condense, translate, then submit with HumanPen

A thesis is not one task. It is a chain of passes over the same document, and the order matters. Check references too late and you reformat sources that do not exist. Condense too early and you cut the evidence you needed for the results section. Translate before you fix the structure and you translate a draft you will throw away. This page describes a pipeline with a deliberate order, and shows where each HumanPen document tool fits.

The pipeline uses tools that exist as separate surfaces on the same product: Citation Fix, Condense, Translate and Humanize, plus Start Project when the work involves data or original drafting. They share a document and a credit balance, which is the practical reason to keep the passes in one place. The rule throughout is that content is protected while form changes: numbers, units, formulas, citations, terminology and claim strength stay as they were.

The sequence is not doctrine. A chapter that needs no shortening skips the condense stage. A thesis written in the submission language skips translation. What matters is that reference verification precedes formatting, and that any structural cutting precedes the final language and wording passes.

Stage one: verify before you format

Start with the sources. Confirm that every in-text marker has a matching entry, that every entry is reachable, and that each source supports the sentence citing it. HumanPen's Start Project review example states that all eleven references were found, one by one; that is a presence check from a delivered project, not a library service. The document-level tools keep citations untouched, which means a broken citation stays broken until you fix it.

The reason to put this first is cost in the broad sense. Reformatting a fabricated reference wastes a pass, and discovering the fabrication after translation means translating a sentence you will delete. One session with the source list is cheaper than repeating four downstream stages.

If your sources live in a reference manager, keep it. HumanPen does not maintain a library; it preserves the citations in your document. The division of labour is clean: the library owns metadata, the document tool owns the pass over wording and form.

Stage two: convert the style, not the argument

Citation Fix is the mechanical stage. A style conversion changes the arrangement of author, year, title and source to match the target convention, and updates in-text markers accordingly. It does not change your sentences, results or the force of a claim. The protected-elements principle applies: citations, numbers, units, formulas, terminology and claim strength are kept.

A journal that changes its style at revision sends you back to this stage alone. That is the cheapest possible revision, because stages one, three and four do not need repeating. Spot-check one reference you know well before and after, then move on.

Stage three: condense to a budget, not to a summary

A thesis chapter over its limit is a budget problem. Condense is listed among the document tools for exactly this kind of pass. The important discipline is to set the budget before the pass and to protect the evidence: the figures, the tables and the citations that carry the argument.

Condensing a literature review is different from summarizing it. A summary produces a new text that stands alone; a condense pass shortens the existing text while keeping the structure and the sources. That distinction is why it belongs before translation and after verification. If you cut a citation here, there is nothing downstream to restore it.

Check the result by reading the topic sentences and the numbers, not every word. If the argument still reads in sequence and the key figures are present, the pass did its job.

Stage four: translate the settled structure

Translate belongs after the content has stopped moving. The tool is listed as a document surface, and the document-level promises apply to it as to the others: formatting is kept, and the file returns editable. For a thesis with equations and tables, verify one of each after the pass. An equation that renders correctly in the source language can still lose a subscript in translation if you do not look.

Keep terminology stable across chapters. The protected list names terminology as an element that should be kept, and that is especially useful when the same construct appears in methods, results and discussion. If you have a glossary, hold the translated terms against it.

Stage five: the final wording pass

Humanize is the last language stage, after structure and content are fixed. Its documented method is to target flagged passages, either selected by you or imported from a Turnitin or iThenticate report, and to rebuild the phrasing while keeping numbers, units, formulas, citations, terminology and claim strength. The file comes back as a DOCX, PPTX or TXT with original styling untouched and no word limit.

Putting this pass last matters for cost and for logic. You are charged only for the words actually rewritten, so a targeted pass on a settled chapter is smaller than a pass on a draft you will still cut. And a rewrite cannot protect a claim you have not yet finalized. If a re-check still shows passages flagged at or above the stated threshold, you import the new report and the remaining passages are rewritten for free. That is a workflow, not a score promise.

Where Start Project enters the pipeline

The document tools operate on files you supply. When the work is not yet a file — an analysis to run, a literature set to read, a first draft to produce from data — Start Project is the entry point. The public workflow is explicit: describe the task and attach files, see a plan, and start only after confirmation. A second check runs before delivery. Revisions are requested in the project, with the scope explained first, a new version delivered and past versions kept.

That model is useful at the front of the pipeline, not the end. Use it to produce the evidence table, the analysis and the first draft. Then export the deliverable and run the document passes above. Mixing the two — editing a project delivery by hand in a separate file — loses the version record that makes the revision path valuable.

Projects are kept for six months after the last activity, with a reminder beforehand, and can be deleted at any time. Export what you need into your own repository once the pipeline is done.

Frequently asked questions

Do all four document tools share one credit balance?

The Start Project pages and developer documentation describe a single balance across the paths, and the developer page states that the agent, skill and API paths spend the same balance. Credit use for each document job depends on the work done.

Should I condense before or after translating?

Before. Cutting a settled draft means translating less text, and removing a citation before translation avoids translating a sentence you will delete.

Does the wording pass change my numbers or citations?

No. Numbers, units, formulas, citations, terminology and claim strength are described as kept exactly as they were; only the phrasing is rebuilt.

Can I skip the reference check if the journal only changed its style?

Yes. A style change at revision is a Citation Fix job. The reference check belongs at the first submission, and repeating it is only necessary if the source set changed.

What file types come back from the document passes?

DOCX, PPTX and TXT files return editable, with original styling untouched. Research-project uploads accept Excel, CSV, Word, PDF and zip files up to five gigabytes in total.
