jamovi vs HumanPen Start Project: You Drive the Menus, or You Approve the Plan

jamovi is the better choice when you want to do the statistics yourself, see each step as you take it, and learn the analysis by running it. It is a free and open statistical spreadsheet: desktop is free forever, Cloud's Guest plan is free with no install and no credit card, the engine underneath is R, and data, analyses and results save into a single reproducible file.

HumanPen Start Project is the better choice when the analysis needs to be specified, executed and written up, and you would rather approve a plan than click through menus. You describe the task and attach the data, the project returns a plan, work starts only on your confirmation, the analysis runs in Python or R, a second AI reviews the result, and what comes back is a .docx report, 300 dpi figures, three-line tables, a .pptx with speaker notes and the code.

The tension is not price — one is free and the other publishes no rate card we could read. It is authorship of the steps. jamovi gives you the menu, the output and the file that holds them. HumanPen takes a specification and returns the finished artefact with the script behind it. The question is whether your time is better spent learning the path or reviewing someone else's.

The difference is who turns the crank

jamovi's design decision is to keep the analyst in the loop. The page describes a spreadsheet you point at, and the engine beneath it is R. Nothing about that arrangement is passive: the software executes an analysis you have chosen and is silent about which one you should choose.

That is not a limitation to apologise for. For teaching, exploratory work and a researcher who wants to understand the model rather than receive it, menu-driven analysis is the right instrument: you see the distribution before you choose the test.

HumanPen Start Project is arranged the other way round. A job moves through five stages — Describe, Plan, In progress, In review, Delivered — under the rule "Plan first, start when you confirm". The plan is not a menu; it is a statement of what will be done, in enough detail to disagree with before any compute is spent.

The public example makes that concrete. The brief is a secondary analysis of the International Stroke Trial, and the plan restates it as a full analysis set of 19,435 patients, a primary endpoint of death or dependency at 6 months, and about 150 missing outcomes handled with a sensitivity analysis. Those three decisions — population, endpoint, missing data — are where a secondary analysis goes wrong, and all three are settled before a table is produced.

So the practical question is not "which tool is more capable". It is "do I want to choose the test, or do I want to approve a specification?" Those are different jobs, and most researchers are better at one than the other.

Two meanings of "reproducible"

Both products care about reproducibility, and they mean different things by it.

jamovi's version is contained. Data, analyses and results save into a single file, so the file is the analysis: hand it to a co-author and they have your dataset, your output and the state that produced it, without loose scripts and screenshots. That is a strong guarantee for a supervision meeting or a teaching exercise, and it travels — one file, no environment to rebuild.

HumanPen's version is procedural. The plan is confirmed against a version, the analysis runs in Python or R, and the code arrives with the report. A review step precedes delivery, shown as "Review passed (round 1)" with named checks: the endpoint matches at 62.2% against 63.5% with P = 0.072, every population adds up, a clean rerun reproduces the results, all 11 references were found. Revisions run to the same logic: request, scope, confirm, new version, old one kept.

The difference shows up months later. A single jamovi file answers "what did we run?" for whoever holds it. A delivered script answers "run it again and show me" for a reviewer who does not trust the file. A paper under revision usually wants the second; a methods course usually wants the first.

Where the analysis actually happens

jamovi runs on your machine with the desktop build, and in the browser with Cloud. The Cloud Guest plan is free, needs no installation and no credit card, which makes it the easiest way to start — particularly for a student on a borrowed laptop.

HumanPen runs the job in an isolated sandbox, one per project, with encryption in transit, no sharing across users and no use for training. The page is explicit that the sandbox is the boundary: your data does not sit in a shared pool, and the project can be deleted completely at any time.

Neither arrangement is obviously safer; they protect different things. Local execution protects against a vendor losing your data, because the vendor never has it. A sandboxed project protects against your own machine being the weak point, and it is the arrangement that lets someone else run the analysis for you.

The page also draws its own limits: analysis is Python or R, SPSS and Stata work is redone in Python or R, Wind and CNKI data must be exported first, GPU training is not yet supported. If your plan depends on training a model, read that line before you upload.

Uploading, and what a finished job looks like

jamovi's unit of exchange is its own file: data, analyses and results in one shareable, reproducible file, and the workflow is a save rather than a submission. The pages we examined do not describe an upload ceiling, because there is no upload: the data is already on your machine.

HumanPen's unit of exchange is a delivery. The intake is stated precisely: Excel, CSV, Word, PDF and zip up to 5 GB total. So is the output: a .docx report, charts at 300 dpi to journal standards, three-line tables and captions, a .pptx with speaker notes, and the code. There is also a writing step, with numbers and citations kept exactly as they are — the before-and-after example shows the same percentages and the same P value rephrased into a shorter sentence, not rounded or restated.

That contrast is the whole comparison in miniature. jamovi returns a session you can keep exploring. HumanPen returns a package you can submit.

Price and governance

jamovi's pricing is the simplest in this category: free. The page says it twice — free and open source, and desktop free forever — and the Cloud Guest plan is free too, with no install and no credit card. There is nothing to meter, nothing to renew and no seat to count, which is the strongest argument the page makes.

HumanPen sells credits rather than subscription seats, so this comparison quotes no per-month figure for it. What it does publish is a set of governance commitments, written for whoever has to defend a data-handling decision: encryption in transit, an isolated sandbox per project, no cross-user sharing, no use for training, deletion at any time, retention of 6 months after the last activity with a 3-day reminder.

Side by side, the trade is clear. jamovi's governance is architectural: the data stays where you put it, and the licence means nobody can change the terms on you. HumanPen's is contractual: the data leaves your machine, and the protections are the ones the vendor commits to in writing. For a teaching dataset the first is enough; for a clinical extract, the second needs reading carefully.

When to choose which

Choose jamovi if you want to run the analysis yourself, or you teach it. The free desktop build, the free Cloud Guest plan and the single reproducible file make it the lowest-friction way from a spreadsheet to a result, and the R engine underneath keeps the ceiling high. For coursework, pilot work and any job where understanding the model matters more than the deadline, it is hard to beat.

Choose HumanPen Start Project if the deliverable is a document, not a result. A paper's methods and results, a clinical report, a grant's preliminary analysis, a reproduction of a published table — these need a plan you approve, a second review before delivery, figures at 300 dpi, three-line tables, a deck with speaker notes and code a reviewer can rerun. The 5 GB total intake also fits a dataset plus its documentation.

Use both if your project has an exploratory phase and a delivery phase. Explore in jamovi: load the data, try three specifications, find the outliers, save the file so the exploration is recoverable. Then write the specification into a HumanPen project, confirm the plan, and take delivery of the report, figures, tables and code. jamovi answers "what is in this data"; the project answers "what does the paper say, and can you prove it".

The mismatch to avoid is treating a menu as a methods section: clicking through a test produces a result, not an argument, and the gap between the two is where most of the writing work sits.

FAQ

Is jamovi free? Yes. It is free and open source, desktop is free forever, and Cloud's Guest plan is free with no install and no credit card.

Do I need to know R to use jamovi? The page describes a graphical statistical spreadsheet powered by R: the interface is the spreadsheet, R is the engine beneath it. Whether that counts as "needing R" depends on how far you go; the pages we examined do not describe an agent that takes a brief and runs it for you.

Can jamovi write the report and the figures for me? The pages we examined describe data, analyses and results saving into one reproducible file. They do not describe delivering a formatted .docx, a 300 dpi figure set, three-line tables and analysis code as a package, so we make no claim either way.

How large a project can I attach to HumanPen Start Project? Excel, CSV, Word, PDF and zip, up to 5 GB total. Analysis runs on Python or R; SPSS or Stata work is redone in Python or R; Wind and CNKI data must be exported first; GPU training is not supported.
