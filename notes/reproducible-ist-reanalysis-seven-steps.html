Can your secondary analysis be reproduced? Seven steps, run on the IST dataset by HumanPen

A secondary analysis of a trial is judged twice: once on whether the conclusion is interesting, and once on whether a stranger with the same file can reach the same number. The second judgment is the one that kills papers in review, and it is entirely mechanical. You can test it before submission.

The judgment up front: reproducibility is not a property of the software. Stata's own site promises "accurate, reproducible results" and ships 19,000+ pages of documentation; RStudio's Open Source Edition is free under AGPL v3. Neither fact makes your table reproducible. What makes it reproducible is a short sequence of decisions, and the seven below are the ones that fail most often. As a worked case, HumanPen's public example reanalyses the IST trial: full analysis set 19,435 patients, primary endpoint death or dependency at six months.

Editorial disclosure: this article is published by HumanPen. Statements about other products come from the public pages we examined on 2026-11-24. No synthetic benchmark was run; prices change, so confirm on the vendor's page.

1. Lock the analysis set and the endpoint before you touch a variable

What it means. State the full analysis set — 19,435 in the IST example — and the primary endpoint — death or dependency at six months — in one sentence each, with the rule that decides membership. Write it before any model runs.

Why this step breaks. Analysis sets drift. Someone excludes a centre, someone drops rows with a blank field "temporarily", and the denominator changes between the abstract and the table. No reviewer will reconstruct your intent from a caption.

How to check. Count the rows in the locked file and print the number into the log. If the number in your table is not printed by code, it is a number someone typed.

2. Decide how missing outcomes are handled, and show the sensitivity

What it means. In the IST example about 150 patients have a missing outcome. The main analysis has to state its assumption, and the sensitivity analysis has to be run as a separate, named output.

Why this step breaks. Missingness is where a result flips. Complete-case and worst-case assumptions can point in different directions, and a single reported P value hides which one you used. Reviewers increasingly ask for the alternative.

How to check. Confirm that the sensitivity analysis exists as its own script and its own table row, not as a sentence in the discussion. If the number of excluded patients is not stated, the reader has to guess the population.

3. Reproduce the main result exactly, to the digit

What it means. The published comparison is 62.2% in the aspirin group against 63.5% in the control group, odds ratio 0.95 (0.89–1.00), P = 0.072.

Why this step breaks. Rounding is the usual culprit: percentages computed from a different denominator, an odds ratio reported to two decimals from an unrounded estimate, a P value that changes when a continuity correction is switched on. Each is small; together they make a table that does not match its own abstract.

How to check. Rerun from the raw file and diff the output against the published table cell by cell. HumanPen's review list treats this as its own item: the primary endpoint is matched at 62.2% vs 63.5%, P = 0.072, as a check rather than a claim.

4. Produce figures at 300 dpi and tables as three-line tables

What it means. Figures at 300 dpi to journal standards, with captions; tables in three-line form, with the denominator visible.

Why this step breaks. A figure exported at screen resolution looks fine in a PDF proof and fails production. A table with vertical rules and shaded headers has to be rebuilt at typesetting, and rebuilding is where a column gets transposed.

How to check. Open the image properties and read the resolution. Count the horizontal rules in the table: three, plus the header separator if your target journal allows it.

5. Verify every reference to its DOI, one at a time

What it means. In the example, the citations are the IST and CAST papers in The Lancet, 1997. HumanPen's review list records the outcome as "All 11 references found, one by one", after a PubMed search with each DOI checked.

Why this step breaks. Citation managers copy metadata, including the errors. A DOI can resolve to a different paper with a similar title; a trial acronym can map to a protocol paper rather than the results paper. Nothing in a formatted bibliography reveals this.

How to check. Resolve each DOI and compare title, journal, year, volume and first author. Do it in a column of a spreadsheet, not from memory.

6. Rerun clean, from an empty environment

What it means. Delete outputs, clear the session, run the whole thing from the entry script, and compare the produced tables and figures against the delivered versions.

Why this step breaks. Notebook state hides order dependence. A cell that only works because a variable was defined three cells earlier will fail for the next person, and a package version pinned in your environment but not in a lockfile will fail in six months.

How to check. HumanPen's review describes a "clean rerun" as an exact reproduction, which is the only version of the check worth running. Run it on a machine that has never seen the project.

7. Have someone else review the four things that matter

What it means. A second reviewer — in HumanPen's case a second AI pass before delivery — checks four items: the primary endpoint matches, each analysis population adds up, the clean rerun reproduces exactly, and all 11 references are found one by one.

Why this step breaks. Self-review checks what you expect to see. The four items above are chosen because each is cheap to check and expensive to get wrong: they are arithmetic and lookups, not judgment calls.

How to check. Ask for the review record, not a summary of it. The page shows the form of the result — "Review passed (round 1)" — because a pass with no named items is not a check.

Three common misconceptions

"Reproducible means rerunning in the same software." Stata's documentation is genuinely deep, and RStudio is genuinely free, but a documented environment reproduces the tool's behaviour, not your decisions. The population rule, the missing-data assumption and the model specification live in your code, or they live nowhere.

"The numbers match, so the analysis is right." Matching numbers prove the arithmetic repeats. They do not prove the endpoint is the trial's endpoint, that the population is the full analysis set, or that the sensitivity analysis was run. Step 7 exists because step 3 can pass while step 1 is wrong.

"A screenshot is evidence." A screenshot is a picture of a number. Evidence is the script, the input file, the printed denominator and the diff. If your archive has no code, you have a picture.

FAQ

Is Stata reproducible out of the box? Its site describes accurate, reproducible results and documents the language across 19,000+ pages, which makes a rerun feasible. Whether your specific table reproduces still depends on your do-file, your data version and your rounding.

Do I need RStudio Pro to reproduce an analysis? No. The Open Source Edition is free under AGPL v3 and runs the same language. Pro adds commercial licensing and priority support, which are organisational questions rather than reproducibility ones.

How many references should a reanalysis verify? As many as it cites. The number in HumanPen's example is 11, checked one by one, and the point is the method — one DOI, one comparison — not the count.

What if my original analysis was done in SPSS or Stata? HumanPen's page states that analyses originally done in SPSS or Stata are performed using Python or R. That is a rewrite, so budget for the rerun in step 6 to be the first true test of the new code.
