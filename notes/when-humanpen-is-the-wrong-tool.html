When HumanPen is the wrong tool: six jobs that need something else

A tool page that only lists reasons to say yes is not much use to anyone choosing one. This page does the opposite. It names the jobs HumanPen does not do, says what to use instead, and then draws the line where the product actually starts. If your task is on the first side of that line, use the other tool and save your credits. If it is on the second, the rest of this page describes what to expect.

The distinction matters because the name "AI document tools" invites a category error. A reference manager, a statistical package, a localization platform and a document rewriter all touch the same manuscript, but they are not substitutes for one another. HumanPen is a document-level service: it uploads a file, runs a job, and returns an editable file. It is not a library, not a native SPSS workspace, not a GPU host and not a permanent archive.

A reference library is not a rewrite

The most common mismatch is someone asking a rewriter to behave like Zotero or EndNote. A reference library stores metadata, resolves identifiers, de-duplicates entries, and keeps a live link between an in-text citation and a bibliography. None of that is a rewriting job. If what you need is a place where six co-authors share one library and resolve DOIs together, get a reference manager.

HumanPen's relationship to references is deliberately narrower. The home page lists citations among the elements that are kept exactly as they were, alongside numbers, units, formulas, terminology and the strength of a claim. The independent-review example states that all eleven references were found, one by one. That is a check on a document you supply, not a library you maintain. The distinction is useful: a converter that quietly renumbers your sources is a problem, and a converter that leaves them alone is a tool you can still use alongside your library.

So the working pattern is not "choose one". Keep the library where it belongs, and use the document tool for the pass that changes wording. You will be able to tell which system is responsible when something looks wrong, because the library still holds the canonical entry.

Native-format replay is a different requirement

A second group of mismatches comes from reproducibility rules that name a specific program. If a supervisor, a journal or a funder requires the analysis to be replayed in SPSS, then a Python or R rerun does not satisfy that requirement, however correct the numbers are. The projects page is explicit that analyses originally done in SPSS or Stata are performed using Python or R. That is an honest scope statement, and it is also a reason to keep SPSS in the workflow when native replay is the deliverable.

There is a middle case worth naming. When the requirement is not "show it in SPSS" but "show defensible code that reproduces the table", the Python or R delivery is exactly the artefact you want. The same page describes a rerun that reproduces results exactly and reports notes on differences. That kind of output is auditable in a way a menu-driven export often is not. Decide which requirement you actually have before choosing.

Wind and CNKI data need the same advance thought. The page asks you to export those formats first. If your source is a database export rather than a clean CSV, the preparation step belongs to you, and it is not a credit question.

The GPU and the archive are hard boundaries

Some limits are not preferences. GPU training is not yet supported, so a project whose core is model training does not belong here. A dedicated cloud computer is provided for research and document work; that is a different resource from a training cluster. Planning around this early saves the cost of discovering it after upload.

Retention is a similar case. Projects are kept for six months after the last activity, and a reminder arrives three days before expiry. You can delete a project at any time. That is a working window, not an archive. If the deliverable must remain reachable years later, put the final files in your institutional repository or your lab's version-controlled store. Treat the six months as time to inspect, revise and export, not as permanent storage.

This boundary is also good discipline. Research records should live in more than one place, and a tool that offers deletion on request is not trying to become your system of record. Export the delivery, keep the code, and write the method note while the project is still active.

Why there is no promise about a score

A tool that promises what a detector will decide is promising something it cannot control. HumanPen's public description is about scope: import a Turnitin or iThenticate report to target flagged passages, and keep layout, citations and original meaning. It also states that numbers, units, formulas, citations, terminology and claim strength stay as they were, and that deliberate typos and grammar errors are not introduced to fool detectors. The documented workflow says that if a re-check still shows a result at or above the stated threshold, you can import the new report and the remaining flagged passages are rewritten for free.

That is a workflow with a stated stopping rule, not an outcome guarantee. It depends on the report you import, the passages it flags, and the result of your re-check. If your requirement is a signed promise about a score, no document rewriter can honestly give it to you. If your requirement is a careful, targeted rewrite that leaves the evidence alone, that is a job this tool is shaped for.

What to do instead, concretely

Start by writing one sentence that names the artefact you need at the end. "A clean DOCX with the same tables and untouched citations" is a document job. "A shared library with stable keys" is a library job. "A replayable SPSS syntax file" is a statistics job. Most disappointments come from letting these three sentences blur into one request.

Then check the input format against the tool. Document work accepts DOCX, PPTX and TXT, with no word limit, and returns the file with its original styling untouched. Research work accepts Excel, CSV, Word, PDF and zip files up to five gigabytes in total. If your input is outside those lists, prepare it first instead of hoping the upload will cope.

Finally, decide who owns verification. HumanPen's workflow includes a plan you confirm before work starts and a check by a second system before delivery. That is useful, but it does not replace your own read of the returned file, your check that the numbers match the source, or your judgement about whether the claim still says what you meant. The tools reduce mechanical error. They do not transfer responsibility.

Frequently asked questions

Can HumanPen replace my reference manager?

No. It keeps citations in a document untouched and can check that references in a supplied document were found, but it is not a library for storing, sharing and resolving metadata. Keep your reference manager.

Can I get my analysis back as SPSS syntax?

Not as SPSS syntax. Analyses originally done in SPSS or Stata are performed using Python or R, and code is part of the delivery. If native SPSS replay is a requirement, keep that step in SPSS.

Is there a word limit on document jobs?

The home page states no word limit for DOCX, PPTX and TXT jobs and says the file returns with original styling untouched. Research-project uploads have their own total size limit, stated as five gigabytes.

How long will my project stay available?

Projects are kept for six months after the last activity, with a reminder three days before expiry, and can be deleted at any time. Export anything you need to keep permanently.

Does the tool guarantee a particular detection result?

No. It documents a targeted rewrite workflow with a free second pass on the passages still flagged in a later report. It does not promise a score, and the page explicitly avoids tricks such as deliberate typos.
