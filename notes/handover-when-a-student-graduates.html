When a student graduates: the analysis handover that keeps a lab's results reproducible with HumanPen Start Project

Every lab has one project that nobody can rerun. The student who built it graduated, the script lives on a laptop that has been wiped, and the paper is cited for a number that no current member can regenerate. The cost is not sentimental: it is a reviewer query, a correction, or a replication that fails for reasons nobody can diagnose.

This is the handover we would run at the end of a project, written so that the next person can reproduce the work with HumanPen Start Project or without it.

Start the handover a month early, not on the last day

The failure mode is a handover compressed into the final week, which produces a zip file and no understanding. Begin four weeks out with one task: the student writes the decisions log, and a second person follows it to reproduce one table. Every gap found in that exercise is a gap that would otherwise have been discovered by a reviewer.

The test is not "is the archive complete". The test is "can someone else produce table one".

Make the canonical dataset a decision, with a date

Labs accumulate derivatives: the merged file, the corrected file, the file with the recoded variable, the file used for the sensitivity analysis. Name one as canonical, record the date it became canonical, and state what was corrected relative to its predecessor.

Then archive the raw exports alongside it. A canonical file with no raw ancestor cannot be audited, and an audit is exactly what a correction request requires.

Write the decisions log as a list of sentences

Not a diary. One line per decision: what was decided, when, and why. "Excluded patients with missing baseline, because the model requires complete covariates; sensitivity analysis includes them with imputation" is the format. Fifty of those lines will save a successor fifty hours.

This log is also the raw material for the methods section, which is why it should be written while the analysis is fresh rather than reconstructed at submission.

Ship the report, the figures and the code together

The minimum reproducible package is the report, the figure sources, and the code that produces both from the canonical data. HumanPen Start Project delivers a report, figures, tables and code as one delivery, and its public example explicitly checks that a clean rerun reproduces the results exactly, which is the property a successor needs most.

If the project was run on HumanPen Start Project, download the deliverables rather than relying on continued access: projects are kept for six months after the last activity with a reminder three days before expiry, and can be deleted at any time. Six months is a useful window for a paper under review; it is not an archive policy.

Record what the numbers were, not only how they were made

Archive the final tables as tables, in a format that does not require the analysis to run: a spreadsheet or a CSV per table, with the numbers exactly as published. When a reader queries a value three years later, the answer should not depend on a library version being installed.

Keep the p-values, the confidence intervals and the denominators. Denominators are the part most often lost, and the part most often queried.

Transfer access before the last day

Accounts, storage, repository permissions and the project workspace all have owners. Write the owner for each, transfer it while the student still has access, and confirm that the successor can open every file. The most common handover failure is not lost data; it is data that exists and cannot be reached.

Put a front page on the archive

The archive needs a first file that a stranger can open: a short readme naming the canonical dataset, the script that produces the report, the version of the report, the person who can answer questions, and the date. Everything else in the folder is evidence for those five facts.

Keep the readme short enough to read in a minute and specific enough to act on. A folder with a good readme is usable by a new member on their first day; a folder without one is a puzzle that only the person who built it can solve, and that person has left.

Run the acceptance test

Three checks, in this order. First, a second person reproduces one table from the canonical data and the script, without asking questions. Second, the report's numbers match the archived tables cell for cell. Third, every reference in the report resolves.

Those three checks are the same integrity checks HumanPen Start Project reports on delivery — populations adding up, a clean rerun reproducing results, references found one by one — applied to the archive instead of to a fresh delivery. The difference is that the archive has to pass them without the person who built it.

The one-hour version, if the student leaves tomorrow

Sometimes the month is not available. In that case do the minimum that makes the work recoverable, in this order: copy the canonical dataset and the script to a shared location, write a page naming the file, the script and the report's version, record the endpoint and the population definitions in three sentences, and have the departing student record a short screen capture of a rerun.

That hour does not produce a handover. It produces a starting point that a successor can use, which is the difference between a project that can be recovered and one that has to be redone.

Then schedule the real handover for the first month of the successor's time. The successor's first task should be to reproduce one table, because that task converts an archive into an understanding.

Frequently asked questions

What if the student used menu-driven software and there is no script?

Then the analysis has to be re-specified from the report and the data before the archive is closed, which is a small project in itself. HumanPen Start Project re-does analyses originally run in SPSS or Stata in Python or R, which produces the missing script as a by-product and makes the result inspectable.

How long should an archive be kept?

Follow your funder and institution, and treat the paper's citation life as the practical floor. A number that is cited can be queried at any time, so the package that produces it should outlive the project's storage defaults.

Who should own the handover?

The supervisor, not the departing student. The student produces the artefacts; the supervisor signs off that a second person could use them.

Is a zip file enough?

A zip file is transport, not a handover. It becomes a handover when it contains the canonical data, the codebook, the script, the decisions log, the report and the figure sources, and when someone else has proved they can use it.
