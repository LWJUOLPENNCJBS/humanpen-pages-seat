Stata vs HumanPen Start Project: A Script You Can Rerun, or a Project You Can Hand Over

Stata is the stronger choice when the analysis is a command line you intend to own. Its public page is built around a single promise — "accurate, reproducible results" — and around the artefacts that make that promise checkable: a script, a dataset, and a manual of 19,000 pages that documents each feature with formulas and fully worked examples. For panel data, survival models, causal inference or a replication package that a referee will open on their own machine, that combination is hard to beat, and the free webinars, NetCourses and thousands of free community additions make the learning curve less steep than the manual's size suggests.

HumanPen Start Project is the stronger choice when the deliverable is a document and the person who needs it is not you. You describe the task and attach the data, the system returns a plan, and nothing runs until you confirm it. Then the analysis is carried out in Python or R, a second AI reviews it, and what comes back is a .docx report with 300 dpi figures, three-line tables and captions, a .pptx with speaker notes, and the code that produced every number.

The difference to weigh is not statistical power. It is who writes the script and who can read the result. Stata hands you an environment and expects you to be the analyst; HumanPen takes the specification, runs it in Python or R, and hands back the report, the figures and the code. If your Stata do-file is the record of your reasoning, keep it. If the record has to be a document a co-author can read without opening Stata, that is a different job.

How the workflows differ

1. Nineteen thousand pages vs one page you sign off

The number that matters on Stata's page is 19,000 — pages of documentation, each feature described with its formulas and fully worked examples. That is an unusual thing to advertise, and it tells you who the product is for: someone who wants to know what the estimator does, not just what button produces it. When a referee questions a specification, the answer is in the manual, with the algebra.

HumanPen's equivalent is much shorter and much more specific: the plan. Before anything runs, the brief is restated in the system's own words. In the public worked example — a secondary analysis of the International Stroke Trial — the plan fixes the full analysis set at 19,435 patients, the primary endpoint as death or dependency at 6 months, and a sensitivity analysis for about 150 missing outcomes. It is a page, not a manual, and its purpose is different: not to teach you the method, but to make sure the method you meant is the method that will run.

Both are forms of documentation. One is reference material you consult; the other is a contract you approve. A project with a wrong specification will run beautifully and answer the wrong question, which is why the second kind exists.

2. Reproducible because scripted vs reproducible because rerun and reviewed

Stata's claim is that results are accurate and reproducible, and the mechanism is familiar to anyone who has kept a do-file: the script and the data are the record, and running them again gives the same numbers. That is a strong property, and it scales — a replication package built this way can be checked by a stranger years later, in the same environment.

HumanPen makes a narrower and more auditable claim. Before delivery, four things are checked and stated as results: the primary endpoint matches (62.2% vs 63.5%, P = 0.072 in the example), every analysis population adds up, a clean rerun reproduces the results exactly, and all 11 references are found, one by one. The code travels with the report, so the rerun is available to whoever receives the file rather than only to whoever wrote the script.

The difference is where the burden sits. A scripted analysis is reproducible if the script is complete and the environment is intact; a delivered project is reproducible if the delivery includes what is needed to rerun it, which is why the code is part of the package rather than an afterthought. Neither is free. The first needs discipline from the analyst; the second needs a specification detailed enough to be executed without you in the room.

3. Who writes the script, and in what language

This is the part worth being blunt about. HumanPen does not run Stata. Its stated position is that analysis runs on Python or R, and that analyses originally done in SPSS or Stata are performed using Python or R. So a Stata user who hands over a project is not buying a Stata run with a nicer report; they are buying a re-implementation, in a different language, against the same specification.

That is fine when the specification is the asset — a clean dataset, a defined endpoint, a model form you can state in a paragraph. It is a poor fit when the analysis depends on a Stata-specific command whose behaviour you rely on, or when the value of the work is precisely that it stays inside the environment your field audits. Being honest about this early saves an expensive misunderstanding: the delivered code will be Python or R, and if your replication package must be Stata, this is not the tool for that package.

Uploading data and what comes back

Stata's public page, as we captured it, does not state an intake size or a list of supported file formats, so we do not assert either. What it does describe is how you learn and extend the environment: free webinars, NetCourses, and thousands of free community-contributed additions that can be searched and downloaded. For a method that is not in the base system, that ecosystem is often the fastest route to working code.

HumanPen states its intake and its limits in the same breath: Excel, CSV, Word, PDF and zip up to 5 GB total; analysis in Python or R; Wind or CNKI data exported first; GPU training not yet supported. The delivery is equally concrete — a .docx report, figures at 300 dpi to journal standards, three-line tables with captions, a .pptx with speaker notes, and the code. For a survey or panel project that ends in a table a co-author has to read, that package is the point.

Price shape and governance

We are not going to quote a Stata price, and this is the paragraph to read carefully if you have seen numbers floating around. Our capture of the Stata pages contained shopping-cart line items for a Stata/MP4 annual licence and for a Stata/BE network maintenance term. Those are cart and maintenance lines attached to a session, not the product's published price, and we do not present them as what you would pay for a licence. Read Stata's own ordering pages on the day you buy.

HumanPen prices by usage rather than by seat: work is billed in real time by what it consumes, failed tasks are not charged, and a plan carries no price up front — scoping is charged, usually a few dozen credits. A round stops and asks once it reaches its limit, a per-project ceiling caps the total, and the figures are final once the delivery settles. Compared with a licence purchase, that is more variable and more granular, and it rewards a group that can write a tight specification up front.

Governance follows the same split. Our capture of Stata's public pages does not describe a per-project sandbox, a training-use policy or a retention period, so we make no claim either way; those questions belong in the licence conversation with the vendor. HumanPen publishes the answers: transport encryption, an isolated sandbox per project, no sharing across users, no use for training, deletion at any time, retention for 6 months after the last activity with a reminder 3 days before expiry. The developer page adds an API at https://api.humanpen.net/v1, plan confirmation with a spec_version, signed short-lived delivery links, and webhooks that carry only the project and its state.

When to choose which

Choose Stata if the analysis is the deliverable — a replication package, a methods paper, a panel or survival model whose specification you will defend line by line. The 19,000 pages, the scripted workflow and the community additions are what you want when the environment itself is part of the argument, and when a co-author will run your code rather than read your report.

Choose HumanPen Start Project if the deliverable is a document for people who will not open a statistical package: a clinical report, a paper's results section, a grant's preliminary analysis, or a published analysis you need reproduced with notes on where the numbers differ. The confirmed plan, the second-AI review and the delivered code are aimed at that reader.

Use both if your group has a methods person and a writing bottleneck. Keep the Stata do-file as the analytical record where the field expects it, and commission the report, figures and tables as a separate, specified job — accepting that the second run is Python or R, and that the two runs have to be reconciled deliberately rather than assumed identical.

The mistake to avoid is treating a licence as a delivery, or a delivery as a licence. One buys you an environment you must operate; the other buys you a document you must specify.

FAQ

Is Stata good for reproducible research? Its public page states accurate, reproducible results and workflows as the product's purpose, and documents each feature across 19,000 pages with formulas and fully worked examples. How reproducible a given analysis is depends on the script and data you keep, which is true of any environment.

How much does Stata cost? We do not quote it. Our page capture showed shopping-cart line items for a Stata/MP4 annual licence and a Stata/BE network maintenance term; those are cart and maintenance entries, not product pricing. Check Stata's ordering pages.

Can a Stata analysis be redone in Python or R? On HumanPen, yes — that is the stated model: analyses originally done in SPSS or Stata are performed using Python or R. The delivered code will be Python or R, not Stata, so a Stata-only replication package is a different job.

Does Stata offer free learning material? Yes. The page lists free webinars, NetCourses, and thousands of free community-contributed additions that can be searched and downloaded.
