What "formatting preserved" actually means in HumanPen, and what it does not

"Formatting preserved" is one of those phrases that sounds absolute and never is. Every document tool means something slightly different by it. This page states exactly what HumanPen's public pages claim, where the claim stops, and what you should check on the file that comes back. The aim is not to sell the phrase but to make it testable.

The claim itself is modest when read literally. HumanPen says a DOCX, PPTX or TXT file comes back with its original styling untouched however long the document. It also names a set of protected elements that are kept exactly as they were: numbers, units, formulas, citations, terminology and the strength of a claim. Only the phrasing is rebuilt. Those two statements together describe a document-level rewrite, not a re-creation of your layout from scratch.

What "untouched styling" does mean

Styling here refers to the visible structure of a document that a word processor manages: paragraph styles, bold and italic runs, link formatting, numbering, table layout and captions. The home page shows a before-and-after example in which a heading, a group statistics table with a control row, and the surrounding numbering remain in place while the sentence above the table changes. The text underneath the example names what survived: bold, links and styles kept; tables and numbering in place; original table layout kept.

For a thesis or a journal submission, this is the part that saves the most rework. A rewrite that returns plain text forces you to rebuild every heading level, reapply every caption style and re-check every cross-reference. A rewrite that returns the same document with changed sentences lets you read the result as a document. That is the practical content of the claim.

Length is part of it too. The page states there is no word limit for these document jobs and that the styling is kept however long the document. In practice, that means the check you perform should be done on the pages you care about most, not only on the first page. A long chapter is where numbering and cross-references tend to drift, if they drift at all.

What it does not mean

It does not mean the tool re-types your equations. Formula and maths are listed as protected and intact, which is a promise not to alter them, not a promise to re-render them more beautifully. If an equation is already ugly in the original, it will still be ugly in the return. The same applies to a table whose design was a poor choice in the first place. Preserving a layout preserves your decisions, good and bad.

It does not mean the tool edits a reference library. Citations are kept, and a supplied report can be checked for references found one by one, but there is no metadata store behind the document. It does not mean the tool fixes a broken citation that was already broken. Protected means unchanged, not repaired.

It does not mean a new document is created in a different template. There is no "convert to journal style" promise in the phrase. If the target venue has its own file template, moving the content into that template is still your job, and doing it before the rewrite is usually easier than doing it after.

Finally, it does not mean a detector score. The pages describe a targeted rewrite and a re-check workflow. They do not state that any particular score will follow, and the protected-elements section explicitly says the tool does not introduce deliberate typos or grammar errors to mislead a detector.

The protected list is the real specification

Of all the wording on the page, the protected-elements list is the most useful to an author. Numbers, units, formulas, citations, terminology and the strength of a claim are kept exactly as they were. Only the phrasing is rebuilt naturally. That list tells you what kind of pass to expect: a linguistic pass over sentences, with the scientific content held fixed.

It also tells you where to aim your verification. A reviewer's worst discovery is not an awkward sentence; it is a changed result. If the tool keeps the number, unit, formula, citation, term and claim strength, then a numeric diff and a citation spot-check cover the high-risk surface. The prose still needs reading, because a natural rewrite can be wrong about emphasis even when every number is right.

This is why the phrase "document-level" matters. A text-box humanizer sees a string. A document-level tool sees a file with tables, headings, references and equations, and the protected list is the statement of what it will not touch in that file.

Targeting changes the arithmetic, not the layout

HumanPen can rewrite passages you select yourself or passages flagged by an imported Turnitin or iThenticate report. The page states that you are charged only for the words actually rewritten. That is a costing rule, but it has a formatting consequence too: untouched paragraphs stay untouched, including their layout. A targeted pass is therefore smaller than a whole-document pass on both dimensions.

The documented re-check workflow follows the same logic. If a later report still shows a result at or above the stated threshold, you import the new report and only the remaining flagged passages are rewritten for free. The point for this page is not the score; it is that the second pass is also targeted. It does not reprocess the whole file, which is why the same tables, headings and citations are still there afterwards.

A verification pass you can actually run

Open the original and the return side by side. First compare the document map or navigation pane: heading levels, section order and page count. Second, pick one table and read every cell against the original. Third, open one equation and one citation. Fourth, search for a link and confirm the target is intact. Fifth, read the paragraphs that changed and ask whether the claim still has the same force. That is five checks and it takes minutes, not hours.

If any of those differ in a way you did not ask for, say so in the project revision request rather than patching the file by hand. Revisions are handled in the project: the scope is explained first, work starts after confirmation, a new version is delivered and past versions are kept. Keeping the fix in the same thread preserves the audit trail.

Frequently asked questions

Does "original styling untouched" apply to long documents?

The home page says DOCX, PPTX and TXT have no word limit and that the file comes back with original styling untouched however long the document. Verify across the whole file, not just the opening pages.

Are equations rewritten?

No. Inline and display maths are described as intact, and formulas are on the protected list. The tool does not improve or redesign an equation.

Will my citations be renumbered?

The pages say citations are untouched. If the original numbering was inconsistent, that inconsistency remains; the tool is not a citation manager.

What about deliberate typos to lower a detector result?

The page explicitly says no deliberate typos or grammar errors are introduced to fool detectors. The rewrite is described as natural phrasing over protected content.

Is a preserved table layout the same as a journal-ready table?

No. HumanPen's research projects deliver three-line tables and captions to standard, but a preserved layout simply means your original layout is still there. Check the venue's own requirements separately.
