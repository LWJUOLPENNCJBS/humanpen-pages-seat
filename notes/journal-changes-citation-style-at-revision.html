When the journal changes citation style at revision: a HumanPen response plan

A revision letter that asks for a new reference style is good news disguised as bad news. The science is accepted; only the arrangement of author, year and title has to change. The trap is treating a mechanical pass as if it were a rewrite, and editing sentences that were never in question. This page separates the mechanical from the substantive and gives an order that avoids both mistakes.

HumanPen lists Citation Fix among its document tools, alongside Condense and Translate. Its protected-elements statement is the reason a style pass is safe on an accepted draft: numbers, units, formulas, citations, terminology and the strength of a claim are kept exactly as they were, and only the phrasing is rebuilt. A citation conversion is the narrowest version of that principle — the arrangement changes, the content does not.

The first row is the one this page is about. The others are listed so you do not accidentally bundle them. A style conversion applied to a draft that also needs a new analysis is fine as a last step, but doing it first means you may repeat it after the analysis changes a number.

Row one: the mechanical pass

A citation style change is a finite, checkable operation. Take one reference you know well — a paper whose author, year and title you can recall without looking — and record it before the pass. Run Citation Fix on the chapter or the whole manuscript. Then find that same reference and confirm that all three fields survived and only their arrangement changed. If they did, the conversion behaved as described.

The same check applies to in-text markers. A style change moves a citation from "(Smith, 2021)" to a numbered form, or the reverse; it does not change which source is cited. Pick one marker in the results section and confirm it still points to the same entry. This is a two-minute check and it catches the only class of error a conversion is likely to make.

HumanPen's humanizer page states that citations are among the elements kept untouched. Although that statement is about a wording pass, the principle transfers: a document tool should not reinvent your sources. A conversion that silently drops an author is a defect, not a feature of the style.

Keep the reply letter aligned with the file

A revision is judged twice: once on the manuscript and once on the point-by-point response. The response letter should say what you changed in the same terms the editor used. If the request was a style change, write that the reference style now follows the journal's convention and that no wording or results were altered. That sentence is easy to defend precisely because a mechanical pass leaves the science alone.

Keep a copy of the pre-revision manuscript before you run anything. When the letter claims nothing else moved, you should be able to prove it by comparing the two files. This is also what lets a co-author review the revision quickly: give them the changed reference list, not the entire paper to re-read. A conversion that is checkable is a conversion you can describe accurately in the response.

Why not rewrite while you are at it

The temptation at revision is to fix everything in the same pass. Resist it for one reason: a revision has an acceptance criterion. The editor asked for a style change, so the success condition is "the style matches and nothing else moved". If you also rewrite sentences, you cannot demonstrate that nothing else moved, and a co-author has to re-read the whole manuscript instead of the reference list.

The protected-elements statement gives you the language to hold this line. Numbers, units, formulas, citations, terminology and claim strength are kept; only phrasing is rebuilt. For a style-only revision, "only phrasing is rebuilt" is more change than you need. The narrowest pass is best.

If the revision letter also asks for a clarity edit, keep it as a separate stage on the specific flagged sentences. The humanize route targets passages you select or an imported report flags, and charges only for the words actually rewritten. That makes a small clarity pass a small job.

When the style change comes with a page limit

Journals often pair the two requests. Shortening an accepted draft is a budget problem, not a summary problem. Condense is the document tool listed for it. Do it after the analysis is final and before the final style pass, because cutting a section removes citations that a previous conversion already formatted.

Hold the key figures and the citations that carry the argument. Read the topic sentences afterwards to confirm the argument still reads in sequence. A chapter that is under the limit but has lost its evidence is a worse submission than one that needs a second cut.

The order for a combined revision is therefore: analysis first, then structural cuts, then the style conversion, then any targeted clarity edit, then a final read of the reference list. Following it means each pass is run once.

Substantive requests belong in the project, not the file

When the editor asks for an additional analysis — a sensitivity check, a different model, a re-run with a defined population — the document tools are the wrong surface. Start Project is described as a workflow in which you state the task, attach files, see a plan, and start only after confirmation. A second check runs before delivery, and revisions are handled in the project with past versions kept.

That version record is useful during a revision, when a co-author may question why a number changed. The plan says what was agreed; the delivery says what came back; the new version says what was changed. Editing the delivered file by hand outside the project discards that trail.

The review example on the public page shows what the check covers: a primary endpoint that matches, analysis populations that add up, a clean rerun that reproduces the results, and references found one by one. Those are the things a revision reviewer will look at. Keeping them in the project makes them answerable.

A submission-day checklist

Confirm the target style by reading the journal's own guide, not a memory of it. Run the conversion on a copy. Spot-check one full reference and one in-text marker. If the letter also set a page limit, confirm the count after the cut. Open one equation and one table. Read the reply-to-reviewers letter against the file and confirm each claim has a corresponding change. Then export and keep the previous version somewhere you can retrieve it.

HumanPen keeps past versions within a project and lets you delete a project at any time. Projects are kept for six months after the last activity. Neither replaces your own archive, so keep the accepted manuscript and the revision in your repository.

Frequently asked questions

Does a style change alter the wording of my paper?

No. The document tools keep wording, numbers, units, formulas, citations, terminology and claim strength; a style conversion changes the arrangement of the citation fields and markers.

Can I run Citation Fix on one chapter instead of the whole manuscript?

The document tools accept DOCX, PPTX and TXT files with no word limit. You can run the pass on the file you supply, which may be a single chapter, and check the result before applying it more widely.

What if the revision also asks for a re-analysis?

Use Start Project for the analytical work. Describe the task, attach the files, confirm the plan, and keep the code and versions from the delivery. Run the citation pass after the numbers are final.

How do I know the conversion did not drop an author?

Spot-check one reference you know well and one in-text marker before and after. That is the highest-yield check for a mechanical style pass.

Is there a guarantee the revised paper will be accepted?

No. The tools describe document operations and a review workflow. No tool controls an editorial decision.
