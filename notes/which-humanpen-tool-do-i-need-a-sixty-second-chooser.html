Which HumanPen tool do I need? A sixty-second chooser

The product has five named surfaces and one project workflow, which is more than enough to make a first-time visitor hesitate. This page is a decision aid, not a tour. Answer one question about what is in front of you — a flagged document, wrong citations, an over-long chapter, a foreign-language draft, or a dataset with no report yet — and it points to the surface that fits. It also names the cases where none of them fit, because that is part of choosing honestly.

The surfaces are Humanize, Citation Fix, Condense, Translate and Start Project, with a Developer API for automation. Their common property is that they operate on documents you supply or tasks you describe, and that protected content — numbers, units, formulas, citations, terminology and claim strength — is kept while form and phrasing change. The differences are about the job, not about quality.

The last three rows are the honest part of a chooser. A page that maps every question to a product is not helping anyone decide. If the job is reference management, GPU training or a guaranteed outcome, the right answer is elsewhere.

Branch one: the flagged draft

If you have a Turnitin or iThenticate report and a DOCX, PPTX or TXT file, Humanize is the surface. You can select passages yourself or import the report to target flagged text. The stated costing rule is that you are charged only for the words actually rewritten, so a short flagged set is a smaller job than a full-document pass.

What comes back is the same kind of file, editable, with original styling untouched and no word limit. Numbers, units, formulas, citations, terminology and claim strength are kept; deliberate typos are not introduced. If a later re-check still shows passages flagged at or above the stated threshold, you import the new report and those remaining passages are rewritten for free. That is a workflow, not a score promise.

Choose this surface when the problem is phrasing. If the real problem is that the underlying result is wrong, no wording pass will fix it.

Branch two: citations and length

Wrong citation style and over-length are both mechanical problems, and both are best handled late in the writing process. Citation Fix changes the arrangement of citations and markers without changing wording or results. Condense shortens a chapter to a budget while keeping the citations and key figures that carry the argument.

The order between them depends on the revision. If the journal changed both the style and the page limit, cut first and convert second, so the style pass runs once on the final text. If only the style changed, run Citation Fix alone and leave the science untouched. A reference that does not exist should be removed before either pass, because both will faithfully format a fabricated source.

Branch three: another language

Translate is the surface when the structure is settled and the content only needs to move languages. The document-level promises still apply: formatting is kept and the returned file is editable. For a thesis with equations or tables, verify one of each afterwards — an equation that renders correctly in the source can lose a subscript if you do not look.

Keep a glossary. Terminology is on the protected list, which is useful when the same construct appears in methods, results and discussion. Translating before the structure is final means translating passages you will delete.

Branch four: a task, not a document

When the input is data and a request rather than a finished file, Start Project is the surface. The public workflow: describe the task, attach files, see a plan, start only after confirmation, receive reports, charts and code after a second check. Revisions are requested in the project, with the scope explained first, a new version delivered and past versions kept.

The example deliverables are a data report, clinical-trial statistics, a research paper and group-meeting slides. The use cases include survey and panel analysis, clinical statistics, reproducing published results, literature reviews, first drafts and slides. That is the right shape for a bounded task with a definition of done.

Before committing, check three stated limits. Analysis runs on Python or R; SPSS or Stata work is re-performed in those languages. Wind and CNKI data must be exported first. GPU training is not supported. Projects are kept for six months after the last activity and can be deleted at any time, so export anything permanent.

Branch five: automation

The Developer API is for server-side integrations. A document job is created by uploading a file and options in one request, with the result downloaded from a temporary URL. Research projects move through states, expose a required-input field when they need you, accept plan confirmation by version, and can run under a credit cap with webhook notifications.

The developer page is explicit about key handling: API keys are for backend services and should be kept out of browsers, mobile apps, public repositories and client-side logs. The agent skill and MCP paths spend the same balance as the API. This is a surface for a pipeline you own, not a replacement for choosing the right tool in the first place.

Frequently asked questions

Can one project do all five jobs at once?

Start Project delivers analysis, charts and a report from a described task. The document tools are separate surfaces for passes over a file you already have. Use the project to produce the evidence and the draft, then the document tools for the final passes.

Which surface keeps my formatting?

All the document surfaces operate at file level. HumanPen states that DOCX, PPTX and TXT return editable with original styling untouched, bold, links, styles, tables and numbering kept, and no word limit.

What if none of the branches fits?

If the job is maintaining a library, training a model, or obtaining a promise about an editorial outcome, none of the HumanPen surfaces is the right shape. Use the appropriate tool or accept that no tool can make that promise.

A useful final check is to say the task out loud in one sentence before you pick a branch. "I need to rewrite the flagged paragraphs in this chapter" is a Humanize job. "I need these references in the journal's style" is Citation Fix. "I need this dataset turned into a report with code" is Start Project. If your sentence contains two different verbs joined by "and", you probably have two jobs and should run them in sequence, with the analytical one first and the document one second. That single habit prevents most of the wrong-tool choices this chooser is meant to avoid.

How do I know which surface I used for a given file?

Each surface has its own request path and its own output. Keep the delivered file, the request and the plan or job record together. In a project, past versions are kept; for a document job, keep your own copy of the input.

Does the chooser account for cost?

Only in a limited way: Humanize charges for words actually rewritten, and project work is charged by usage with a plan you confirm before starting. Read the current public pricing page for rates rather than relying on numbers remembered from another page.
