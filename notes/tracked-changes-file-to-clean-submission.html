From a supervisor's tracked-changes file to a clean submission with HumanPen

A supervisor returns a DOCX full of insertions, deletions and comments. The science is settled and the piece is still not submittable, because a submission system will not accept other people's markup. Turning that file into a clean copy is a document problem with a data problem inside it: you must accept the right changes and keep the numbers intact. This page describes the pass and shows where HumanPen's document tools fit, and where they do not.

The relevant promise is about the file. HumanPen states that DOCX, PPTX and TXT files return editable with original styling untouched, however long the document, and that bold, links, styles, tables and numbering are kept. Numbers, units, formulas, citations, terminology and claim strength are protected during a wording pass. Those statements are about preserving a document, not about deciding which reviewer comment was right — that decision stays with you.

The first three rows are markup to resolve. The last four are content changes hiding inside markup, and they are where a clean-up pass can do damage if it is blind to the protected elements.

Step one: resolve the changes as a person

Before any tool touches the file, accept or reject the tracked changes in your word processor. There is no shortcut for this, because each decision is a judgement about your own argument. Work through the document once with comments visible and answer each one, either in the comment thread or by making the change and then deleting the comment.

Pay particular attention to edits touching numbers and claim strength. A supervisor who changes "was associated with" to "caused" may be asking a question rather than asserting a fact. A corrected value in a results table must match the analysis file, not just look plausible. The public review example is a useful model for the standard: a primary endpoint that matches, populations that add up, a rerun that reproduces the results, and every reference found.

Once the file has no visible markup, you have a clean copy with the accepted decisions baked in. That is the input for a document pass. Feeding a still-marked file into a rewrite risks treating insertions, deletions and comments as prose.

Step two: keep the decision record

A clean file loses the history of what was decided. Keep it somewhere else. A short table with the comment, your decision and the reason is enough, and it saves an argument at proof stage when a co-author asks why a sentence changed. In a Start Project, the equivalent record is the version history: revisions are requested in the project, the scope is explained first, work starts after confirmation, a new version is delivered and past versions are kept.

If the supervisor's markup produced enough changes that the prose now reads unevenly, this is the point to consider a targeted wording pass. HumanPen's humanize surface rewrites passages you select or passages flagged by an imported report, and charges only for the words actually rewritten. Selecting only the paragraphs that changed keeps the rest of the accepted manuscript untouched.

Step three: the wording pass, with protected elements on

The stated method of the wording pass is to rebuild phrasing naturally while keeping numbers, units, formulas, citations, terminology and the strength of a claim exactly as they were. The page also says that deliberate typos and grammar errors are not introduced to fool detectors. That is a good description of the boundary for this job: the tool may make a sentence read cleanly, but it may not change what the sentence claims.

After the pass, verify the format layer. The file should still be a DOCX, with headings, bold, links, tables and numbering in place and the original table layout kept. Open a multi-page table and an equation, not just the first paragraph. If the supervisor had reformatted a section, that reformatting is preserved as part of the original styling, so check it against the journal's requirements separately.

For a long thesis, do the check on the sections that changed and on one section that did not. The unchanged section is a control: if it changed shape, something went wrong with the file handling.

When to send the clean copy back through a project

If the supervisor's comments asked for an analysis change rather than a wording change, the clean copy is not the end of the job. Start Project handles revisions as new rounds with an explained scope and a preserved version history. Send the specific request — re-run the sensitivity analysis with the corrected coding, rebuild the forest plot with the new endpoint — rather than attaching the marked-up file and hoping the intent survives. The plan step exists to turn a comment into a checkable instruction.

This is also where the data dictionary earns its place. A comment that says the exclusion rule changed is only actionable if the coded variable and its rule are written down. The public example is explicit about naming the analysis set and how missing outcomes are handled. Mirror that in your request and the returned version can be checked against the comment that prompted it, instead of against your memory of a conversation.

Step four: style, then submit

A submission system may require a specific citation style. That is a Citation Fix job, and it belongs after the wording pass so that it is done once. The conversion changes the arrangement of citations, not the wording or the sources. Spot-check one full reference and one in-text marker, then confirm the file opens cleanly in the word processor you will upload from.

Keep the marked-up original, the clean copy and the decision record together. A journal that asks for a further change at proof stage is much easier to handle when you can see what was already accepted. Projects on HumanPen are kept for six months after the last activity with a reminder, and can be deleted at any time, but your own repository should hold the final files permanently.

Why not let a tool decide the changes

A rewrite tool sees text, not authority. It cannot know that the supervisor's deletion was tentative, that a comment was addressed in a later meeting, or that a changed number was a typo in the supervisor's read of the table. Those are decisions about evidence and people. The tool's value starts after you have made them, when the clean copy needs a careful pass that preserves everything you just decided.

This is the honest boundary of the whole workflow. Document tools make a settled manuscript cleaner and correctly formatted. They do not settle the manuscript. If you still have open comments or unresolved disagreements with a supervisor, resolve them first; no amount of formatting will substitute.

Frequently asked questions

Can HumanPen accept tracked changes for me?

The document passes operate on the file you supply. Resolve insertions, deletions and comments in your word processor first, then submit the clean copy for a wording or formatting pass.

Will a wording pass change numbers my supervisor corrected?

No. Numbers, units, formulas, citations, terminology and claim strength are listed as protected and kept exactly as they were. Verify the corrected value against the analysis before the pass, though — the tool preserves what is in the file.

Are comments turned into body text?

A comment is markup, not prose. Resolve and remove comments before submitting the file for a pass, so that only body text is rewritten.

Does the returned file keep my tables and headings?

The home page states that bold, links and styles are kept, tables and numbering are in place, and original table layout is kept, with original styling untouched and no word limit.

What if the revision also changes the citation style?

Run Citation Fix after the wording pass and any structural cuts, so the style conversion is done once on the final text.
